Introduction to peRidial

Overview

peRidial is a standardised R framework for ingesting, validating, and summarising clinical peritoneal dialysis (PD) unit data. Nested S3 classes represent the PD unit, its patients, their catheters, and peritonitis episodes, supporting reproducible calculation of the ISPD-recommended peritonitis rate and peritonitis-free percentage indicators from longitudinal catheter and infection records.

This vignette walks through the core classes and a first worked example.

Installation and setup

# install.packages("remotes")
remotes::install_github("ernestcaballero/peRidial")

Note: peRidial includes compiled C++ code (via Rcpp), so installing from source requires a working compiler toolchain: Rtools on Windows, or the Xcode Command Line Tools on macOS (xcode-select --install). Linux users typically have a compiler available already.

Load the package. The package name is all lowercase:

library(peridial)

A first example

The example uses two synthetic Excel files that ship with the package, covering the 2025 reporting year for a fictional unit:

  • a3_2025.xlsx is the unit (A3) file. Each row is one PD catheter, with the patient’s demographic details, PD start and stop dates, any change of dialysis modality, and death or transplant dates. The example file has 60 patients with one catheter each.
  • pe_2025.xlsx is the peritonitis episode (PE) file. Each row is one peritonitis episode: the date of infection, the organism(s) cultured, the date of the last antibiotic dose, and whether the episode led to hospitalisation, catheter removal or a transfer to haemodialysis. The example file has 18 episodes.

No real patient data is included. The column names follow selected items from the ANZDATA Registry data dictionary (for example the AnzdataPatients, AnzdataCourseOfTreatments and AnzdataPeritonitisEpisodes tables). Catheter-level fields that ANZDATA does not collect, such as insertion date, procedure type and removal reason, follow typical PD unit records.

Building a pd_unit

Building from raw data

pd_unit() reads the two files and builds the whole object in one call. Choose a reporting period with a start date \(t_0\) and an end date \(t_1\), usually the first and last day of the reporting year. Dates are given in YYYY-MM-DD format.

t0 <- as.Date("2025-01-01")
t1 <- as.Date("2025-12-31")

unit <- pd_unit(
  unit_data_path = system.file("extdata", "a3_2025.xlsx", package = "peridial"),
  infection_data_path = system.file("extdata", "pe_2025.xlsx", package = "peridial"),
  t0 = t0, t1 = t1, unit_id = "Wellington PD Unit"
)

unit
#> <pd_unit> Wellington PD Unit 
#>   Reporting period      : 2025-01-01 to 2025-12-31
#>   Patients              : 60 (10 incident)
#>   Catheters             : 60
#>   Peritonitis episodes  : 18
#>   Total patient-years   : 50.94

Any data-quality problems found while building (for example an episode that cannot be matched to an active catheter) are collected and reported together as a single warning. Set strict = TRUE to make them an error instead.

Using your own data

Important: the ingestion pipeline is designed around the synthetic dataset described above. Raw exports from ANZDATA or a unit’s own system will not load as they are: ANZDATA uses different column names (for example IinfectionDate and GenderCode) and stores most values as codes, while peRidial expects plain values such as "Female" or "Any PD to HD". Rename the columns and decode the values first.

Your files must use the same column names as the example files. Differences in capitalisation, spacing and punctuation are ignored, so Patient ID, patient_id and PatientID are all accepted. A different name is not: Infection Date will not be recognised as Date of Infection.

File Required columns Optional columns
Unit (A3) Patient ID, Insertion Date, PD Start Date Date of Birth, Gender, Ethnicity, Primary Kidney Disease, Height, Weight, Cigarette Smoking Status, Diabetes Type, Procedure Type, PD Stop Date, Removal Reason, Dialysis Type, Dialysis Modality Change, Modality Change Reason, Date Modality Change, Date of Death, Cause of Death, Transplant Date
Peritonitis (PE) Patient ID, Date of Infection, Organism Last Dose Antibiotic, Overnight Hospitalisation, Days Hospitalised, Catheter Removed, Catheter Removed Date, Interim HD, Permanent HD, First Dialysis Date, Last Dialysis Date

A missing required column stops the build with an error that lists what was found. A missing optional column is filled with NA without a warning, so check the spelling of optional columns carefully. A misnamed Date of Death or PD Stop Date, for example, means patients are not censored and patient-years are overstated.

Values should follow these formats:

  • Dates can be Excel date cells or text in YYYY-MM-DD format.
  • Yes/no columns accept Yes/No, Y/N, TRUE/FALSE or 1/0.
  • Several organisms for one episode go in one cell, separated by commas.
  • A permanent move to haemodialysis is recorded as Any PD to HD in Dialysis Modality Change.

Then point pd_unit() at your own files:

unit <- pd_unit(
  unit_data_path = "path/to/your_a3_file.xlsx",
  infection_data_path = "path/to/your_pe_file.xlsx",
  t0 = as.Date("2025-01-01"),
  t1 = as.Date("2025-12-31"),
  unit_id = "Your PD Unit"
)

Building object by object

If your data cannot be put into the two-file layout, the objects can be built directly with the constructors, from the bottom up: episodes first, then the catheter that owns them, then the patient.

pd_infection() classifies each episode against the patient’s previous one, so pass the earlier episode as prior_episode:

ep1 <- pd_infection(
  patient_id = "ABC1234",
  infection_date = as.Date("2025-03-10"),
  organism_list = list("Staphylococcus aureus"),
  last_dose_antibiotic = as.Date("2025-03-31")
)

ep2 <- pd_infection(
  patient_id = "ABC1234",
  infection_date = as.Date("2025-04-15"),
  organism_list = list("Staphylococcus aureus"),
  last_dose_antibiotic = as.Date("2025-05-06"),
  prior_episode = ep1
)

ep2$episode_type
#> [1] "relapsing"

The second episode is the same organism within four weeks of finishing antibiotics, so it is classified as relapsing. Under ISPD definitions a relapse continues the earlier episode, so it is not counted towards the peritonitis rate.

catheter <- pd_catheter(
  patient_id = "ABC1234",
  catheter_id = "ABC1234_01",
  insertion_date = as.Date("2024-11-02"),
  procedure_type = "Laparoscopic",
  pd_start_date = as.Date("2024-11-20"),
  infections = list(ep1, ep2),
  t0 = t0, t1 = t1
)

patient <- pd_patient(
  patient_id = "ABC1234",
  catheters = list(catheter),
  t0 = t0, t1 = t1,
  gender = "Female",
  date_of_birth = as.Date("1961-06-14")
)

patient
#> <pd_patient> ABC1234 
#>   Reporting window     : 2025-01-01 to 2025-12-31
#>   Status               : prevalent
#>   Catheters            : 1
#>   Peritonitis          : 1
#>   Censoring          : still active on PD
